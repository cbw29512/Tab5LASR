# LASR Target Template & Shot Timer MVP (offline browser)

**Status:** browser-only functional prototype; **not firmware**, not a working camera or laser detector.

## Run

Open `index.html` in current Chrome or Edge (file:// works). No server, dependencies, account, Internet, phone or Tab5 connection needed. This is designed at 1280×720 landscape and adapts to laptop/mobile widths.

## User workflow

1. Click **CHOOSE TARGET**; select Bullseye, Five Dot Drill, Training Silhouette, Plate Rack, or Blank Custom.
2. Drag the four green calibration handles until they match the **illustrative** paper in the preview.
3. **CONFIRM & SAVE ALIGNMENT** stores geometry under that template in the browser's localStorage. Confirmation is required after every reload. Each target keeps its own corners.
4. Choose 3/5/10 seconds, then **START SHOOTING**. Audible countdown ends with a GO beep; the timer starts at GO.
5. Click **DEMO SHOT** or the preview to add a **simulated** shot. It logs elapsed time, split, target zone, and score.
6. Pause, resume with another countdown, End Session, or export simulated shot details as CSV.

## Scope and safety

- **No live camera feed.** Simulated paper target artwork is deliberately labeled.
- **No SIRT detection.** Demo Shots are manually generated by browser clicks, not observed flashes.
- Browser localStorage is **not** Tab5 non-volatile storage, microSD or cross-device sync. CSV download is user-initiated.
- Display Color 2/4 is a design reference only; it never changes raw camera data.
- Do not merge into flashable firmware until the existing camera/MJPEG/Web firmware size, C6 compatibility, calibration storage, and battery gates are resolved.

## Validation

Run `node --test tests/*.test.mjs` for deterministic template, profile persistence, geometry, timing, and offline-control contract tests. Run `node --check *.js` for source syntax checks. End-to-end physical-browser and Tab5 tests remain separate acceptance gates. Every authored source file is under 150 lines; no external dependencies are loaded by the web app.
